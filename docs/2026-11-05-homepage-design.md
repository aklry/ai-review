# 首页：以训练行动为中心

调研日期：2026-11-05。参考官方公开产品介绍，未登录体验，以下布局是结合本项目能力的设计判断，并非照搬竞品登录后的首页。

## 产品参考

- [Huru](https://huru.ai/)：围绕选择岗位或提供 JD、模拟面试、查看复盘与下一步改进组织体验。借鉴明确的训练入口和练后复盘。
- [Yoodli](https://yoodli.ai/use-cases/interview-preparation)：强调岗位场景、模拟与追问、反馈及后续练习。借鉴把重点放在用户下一步行动。

## 本次实现

首页不再展示 API 检测、服务地址和写死的 10/20/30/40% 权重。原数值是能力评分权重，并非用户成绩。评分逻辑不变，真实分数继续在报告和历史复盘中展示。

1. 主区域：首次使用显示“开始首次训练”；有未完成会话时显示目标岗位、主问题进度和“继续训练”；待结束会话显示“前往生成报告”。仍可主动新建训练。
2. 右侧：最近一场训练的复盘入口，没有完成记录时介绍复盘用途。
3. 下方：最近三场训练，展示岗位、时间、状态、真实答题进度及继续/复盘入口；无记录时显示简历与岗位 → 模拟问答 → 复盘的三步指引。
4. 加载中使用骨架屏；加载失败显示重试，不能把失败当成首次使用或零成绩。

复用现有历史接口，独立按状态查询进行中、待生成报告和已完成会话；因此较早的未完成会话不会因为不在最近三条记录中而丢失入口。复盘区的“最近”沿用接口的开始时间排序。新建训练复用现有 restart 清理当前本地配置，已持久化会话仍可在历史中恢复。

不增加尚未实现的专项练习按钮、推测性的薄弱项、连续打卡或跨场平均分。后续专项练习落地后，再把报告中的具体改进项接成可执行入口。
