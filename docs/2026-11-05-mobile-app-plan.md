# AI 面试训练助手 · 个人移动端规划

2026-11-07 更新。面向本人使用，先交付可安装在自己手机上的 Android APK，后续按使用需要适配 iOS。

## 我会怎样用它

平时在电脑上整理简历、粘贴岗位描述、开始训练。拿起手机后，首页直接显示这场训练的岗位和当前进度，点「继续」就能答下一题。偶尔只有手机在手边时，也可以粘贴简历文本和岗位描述，新开四题短场或八题标准场。

首版保留两个入口。「训练」负责继续或新建训练，「记录」负责翻看历史。连接地址放在首页设置里，首次配置后记住。手机和电脑连接同一套 API 与数据库，沿用现有的 `local-user` 和历史记录。

## 首版做什么

| 使用场景 | 手机上要做到                                                                                                     |
| -------- | ---------------------------------------------------------------------------------------------------------------- |
| 接着练   | 读取服务端的未完成会话，区分进行中、已暂停和待生成报告。恢复时遵循原会话的训练模式。                             |
| 开新场   | 在手机上粘贴简历文本与岗位描述，完成岗位分析后选择四题或八题。需要从 PDF/DOCX 导入时，首版沿用桌面端的文件入口。 |
| 回答一题 | 一屏一题，支持键盘和输入法听写。逐题辅导提交后看反馈，完整模拟按服务端规则在结束后复盘。                         |
| 中途离开 | 按会话和题目保存本机草稿。重开时先查服务端进度，仍在同一题才恢复草稿。若另一台设备已提交，直接显示最新进度。     |
| 回头看   | 在历史记录中查看报告、原回答、评分依据和参考答案。未测评维度显示「未测评」。                                     |

资料准备、专项练习和录音可以按实际使用频率逐步搬到手机。仓库已有专项练习接口和桌面交互，后续可从手机报告接入。桌面转写调用 Windows 本机识别器，Android 端可先使用手机输入法的语音输入。需要保存原音、逐题回听时，再做应用内录音。详见[现有训练流程](./2026-11-07-interview-training.md)。

## 怎么连接自己的数据

开发期可先连接本机或局域网 API。正式自用时，NestJS API、PostgreSQL 和简历文件存储运行在服务器上。Android 和桌面端指向同一个 HTTPS API 地址。电脑关机时，手机仍可通过 Wi-Fi 或移动数据开场、答题和看报告。断网期间保留本机草稿，重新连接后先查询该题的提交状态。

继续用 `local-user` 关联自己的资料和训练。如果 API 通过公网提供，建议在 HTTPS 入口或 API 统一验证设备令牌。手机和电脑各配置一次各自的令牌，凭据存入系统安全存储，设备丢失时可单独撤销。若服务器只通过已有私人 VPN 访问，可沿用它的设备身份控制。两种方式都可以免注册。数据库和对象存储仅供服务端访问，模型密钥仅由 API 持有。

从本地切换到服务器时，先暂停本地写入，一并迁移 PostgreSQL 数据和私有存储中的简历文件。核对一场旧训练、报告和对应简历文件后，再切换两端的 API 地址。之后两端都以服务器上的训练进度为准。

## 如何实现

沿用 Vue 3、TypeScript、Ionic Vue 和 Capacitor 的方案，在 `apps/mobile` 建立 Android 客户端。手机与桌面复用 `packages/contracts`、现有 API 和服务端评分逻辑。客户端显式传入 API 地址，把共用的请求逻辑从依赖 `window.desktopApi` 的初始化代码中提取出来。

首个真机验证使用一场桌面端已创建的训练，检查 WebView 到开发 API 的连通性。部署时通过桌面端已有的 `API_BASE_URL` 和手机的连接设置切换地址，并让服务端允许两端实际使用的客户端来源。随后验证键盘、返回键和切后台。提交超时先查询该题的服务端状态，确认尚未提交才允许重试。

### 技术栈与第一阶段交付

| 技术                        | 用途                                            |
| --------------------------- | ----------------------------------------------- |
| Vue 3、TypeScript、Vite     | 开发和构建独立的手机页面                        |
| Ionic Vue                   | 移动端页面容器、滚动和触屏交互                  |
| Pinia                       | 保存正在浏览的训练以及请求状态                  |
| Axios、共享契约             | 调用 NestJS 接口，校验历史和复盘数据            |
| Capacitor 8、Android Studio | 将前端构建产物打包进 Android 工程，连接真机调试 |

第一阶段从桌面已有会话进入。打开手机后能找到未完成训练、恢复暂停的题目、保存草稿、提交回答，并在桌面刷新后看到同一进度。区分逐题辅导和完整模拟的反馈时机。手机独立开新场属于下一阶段。

依赖由项目维护者在仓库根目录执行 `pnpm install`。运行移动端需要 Node.js 22+，构建 APK 还需要 Android Studio 和 Android SDK。[Capacitor 环境要求](https://capacitorjs.com/docs/getting-started/environment-setup)

## 开发顺序与验收

### 运行第一阶段客户端

当前工作区已实现连接设置、继续桌面会话、暂停后恢复、按题保存草稿、提交回答、生成报告和历史复盘。真机验收待安装依赖并连接 Android 设备。共享 HTTP 与会话调用位于 `packages/api-client`，桌面和手机各自提供连接地址。

以下命令从仓库根目录执行。先由维护者安装依赖，启动已配置好的 API，并在桌面端创建一场训练。

```powershell
pnpm install
pnpm -F @interview-assistant/contracts build
pnpm -F @interview-assistant/mobile dev
```

在浏览器打开 `http://localhost:5174`。开发时默认地址 `/api` 由 Vite 代理到本机 3000 端口。生产构建默认连接 `http://175.178.92.165:3100/api`。可在首页「连接设置」保存自己的 HTTPS 地址，也可以在构建时通过 `VITE_API_BASE_URL` 设置默认值。

Android SDK 准备好后，首次生成原生工程并用 Android Studio 运行。

```powershell
pnpm -F @interview-assistant/mobile build
pnpm -F @interview-assistant/mobile android:add
pnpm -F @interview-assistant/mobile android:open
```

后续重新构建页面后运行 `pnpm -F @interview-assistant/mobile android:sync`。安装版默认来源是 `https://localhost`，在 API 环境配置 `MOBILE_ORIGIN=https://localhost` 并重启 API。

如本地 API 尚无 HTTPS，可保留 Vite 开发服务运行，用 USB 连接已启用调试的 Android 手机。生成原生工程后执行下列命令，WebView 将加载经 USB 转发的本机页面，API 请求仍由 Vite 代理。[Capacitor 真机运行命令](https://capacitorjs.com/docs/cli/commands/run)

```powershell
pnpm -F @interview-assistant/mobile exec cap run android --live-reload --host localhost --port 5174 --forwardPorts 5174:5174
```

### 里程碑

按一名熟悉项目的开发者全职投入、现有后端正常运行、有可用 Android 真机估算。

| 顺序                | 可验收的结果                                                                                                                   | 估算         |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------ |
| 1. 真机接续一场训练 | 安装 APK，连接个人后端，打开电脑上创建的会话，在手机答一题，电脑刷新后看到同一次提交。                                         | 1–2 个工作日 |
| 2. 完成日常训练     | 在手机上新建或继续训练，完成短场或标准场，生成报告，从记录页重新打开逐题反馈。                                                 | 3–5 个工作日 |
| 3. 验证日常中断     | 锁屏、杀进程、Wi-Fi 中断和提交响应丢失后都能恢复。确认同一题只记一次，草稿不会回填到下一题。生成可重复安装更新的自用签名 APK。 | 2–3 个工作日 |

上述 Android 文字训练客户端估算为 **6–10 个工作日**。服务器部署、凭据接入及旧数据迁移另计，工期取决于服务器现有环境和访问方式。部署验收时关闭个人电脑，用手机移动数据完成一次训练并生成报告。重新打开桌面端后应能读到同一份报告，未获授权的设备应无法读取训练记录或发起模型调用。
