# 面试助手 Agent 产品与技术方案

> 版本：v1.3  
> 日期：2026-08-24  
> 已确定范围：面向 3-5 年经验的前端与 AI 技术求职者；模型采用云端优先部署。后续可扩展至企业招聘团队。

## 1. 产品结论

推荐将产品定位为 **“合规的 AI 面试训练与授权辅助平台”**，而不是实时替用户回答问题的工具。

核心价值是把用户的简历、目标岗位 JD、练习记录和复盘结果串成长期成长闭环：

```text
导入简历与 JD
        ↓
生成岗位能力地图与训练计划
        ↓
AI 模拟面试与动态追问
        ↓
逐题报告、证据化反馈与薄弱项练习
        ↓
下一次训练计划和能力趋势
```

首版面向 **3-5 年经验的前端与 AI 技术求职者**，支持中文、英文及中英混合面试。企业端的题库、评分卡、ATS 集成不进入 MVP。

### 1.1 目标人群与能力地图

首批用户通常已具备项目经验，面试的关键不在基础概念背诵，而在于技术取舍、项目深度、系统设计和结果表达。能力模型按以下优先级设计：

1. **前端工程能力**：Vue/React、TypeScript、浏览器原理、性能优化、工程化、组件设计、Node.js/BFF。
2. **AI 应用能力**：LLM 应用开发、RAG、Agent、提示词与工具调用、评估、可观测性、成本与安全治理。
3. **项目与系统能力**：需求拆解、架构取舍、稳定性、可扩展性、指标设计和线上问题复盘。
4. **面试表达能力**：STAR 叙事、技术决策的因果链、量化结果、跨团队协作和中英双语表达。

## 2. 合规边界

不实现以下能力：

- 规避录屏、屏幕共享、系统检测或面试平台检测。
- 在未经面试官同意的真实面试中生成实时作答内容。
- 隐藏录音、静默采集系统音频或虚构简历经历。

产品提供三种明确模式：

| 模式         | 目标                 | 允许能力                                                |
| ------------ | -------------------- | ------------------------------------------------------- |
| 准备模式     | 面试前准备           | 简历/JD 分析、题目生成、STAR 故事库、公司研究清单       |
| 模拟模式     | 受控练习             | AI 面试官、语音/视频录制、追问、复盘和专项训练          |
| 授权辅助模式 | 已获许可的面试或演练 | 实时字幕、计时、要点笔记和会后总结；需显示录音/同意状态 |

该边界能降低诚信、隐私、平台规则和品牌风险，也能让产品服务于可持续的训练效果，而非一次性投机需求。

### 差异化机会

市场上通常只覆盖“实时提示”或“单次练习”之一。首版应突出以下差异：

1. **证据化辅导**：每条建议必须引用简历、JD 或本轮回答片段，避免空泛话术。
2. **长期训练闭环**：根据多次练习形成能力趋势和下一步计划，而非单场报告。
3. **中英双语岗位理解**：支持中文 JD、英文术语、混合表达和跨国面试。
4. **合规与隐私优先**：明确授权、云端数据治理、可导出/删除数据；本地转写只作为后续可选能力。

## 4. MVP 功能范围

### 4.1 准备中心

- 上传 PDF/DOCX 简历，或直接编辑个人档案。
- 粘贴 JD，提取职责、硬技能、软技能、优先级和潜在考点。
- 自动生成岗位能力地图、高频题清单、模拟计划和待补充经历。
- 建立可复用的 STAR 故事库，每个故事关联项目、行动、结果和量化指标。

### 4.2 AI 模拟面试

- 选择岗位、语言、面试轮次、难度和目标公司类型。
- 支持文字优先 MVP；第二阶段支持麦克风语音。
- AI 按能力维度提问，并根据回答追问，不按固定题单机械播放。
- 用户可要求澄清、跳题、暂停、结束；所有行为形成会话事件。

### 4.3 复盘报告

- 每题给出：回答摘要、评分、证据、缺口、改写方向和下一题训练建议。
- 分别评估内容相关性、STAR 完整度、量化结果、技术准确性、表达清晰度和岗位匹配度。
- 语音模式增加语速、停顿、填充词、话语占比等指标，但不得将其作为录用判断。
- 生成可执行的 7 天训练计划，并以历史表现调整难度。

首版岗位匹配总分采用固定权重，满分为 100 分：

| 评分维度  | 权重 | 重点考察                                           |
| --------- | ---: | -------------------------------------------------- |
| Vue/React |  10% | 框架原理、组件设计、状态管理、性能优化与工程实践   |
| AI 应用   |  20% | LLM 应用、RAG、Agent、评估、可观测性、成本与安全   |
| 系统设计  |  30% | 架构拆分、可扩展性、稳定性、数据流、容量与技术取舍 |
| 项目深度  |  40% | 个人贡献、决策因果、量化结果、线上问题与复盘       |

每个维度保留题目级明细和证据引用；总分只用于训练优先级和能力趋势，不作自动化录用判断。

### 4.4 首版题库蓝图

首版建设 **120 道规范题**，每题包含题干、追问树、参考证据、评分 rubric 和标签。题目比例与总分权重保持一致；AI 仅可在规范题基础上生成不计分的追问。

| 维度      | 题目数 | L1 基础 | L2 进阶 | L3 挑战 | 核心题数 |
| --------- | -----: | ------: | ------: | ------: | -------: |
| Vue/React |     12 |       4 |       6 |       2 |        4 |
| AI 应用   |     24 |       7 |      12 |       5 |        6 |
| 系统设计  |     36 |      10 |      18 |       8 |        8 |
| 项目深度  |     48 |      14 |      24 |      10 |       10 |
| 合计      |    120 |      35 |      60 |      25 |       28 |

- **L1 基础**：能清晰说明原理与亲自做过的实现，适合热身和发现概念缺口。
- **L2 进阶**：包含两个以上约束，例如性能、成本、稳定性、协作或历史包袱；这是 3-5 年经验用户的默认难度。
- **L3 挑战**：开放的真实业务场景，需要给出取舍、容量估算、失败预案和验证方式。

标准 60 分钟模拟从题库抽取 8 道计分题：Vue/React 1 题、AI 应用 2 题、系统设计 2 题、项目深度 3 题；得分仍按 10/20/30/40 的维度权重聚合，而不是按题目数量平均。首场默认以 L2 为主（1 道 L1、5 道 L2、2 道 L3），后续依据薄弱维度调整。

每场标准模拟必须在每个维度命中至少一题核心题；28 个核心点由训练计划跨多场累计覆盖。这里的“必须答”表示被抽到后必须评分，不表示自动淘汰；低于 3/5 分会被列为下一轮训练的硬性补弱项。

| 维度      | 必须覆盖的核心题                                                                                                                     |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Vue/React | 用户选定框架后，覆盖一次渲染/响应式与状态更新链路、一次组件边界与状态设计、一次性能诊断与优化；Vue 与 React 各维护两道框架特定核心题 |
| AI 应用   | RAG 端到端设计及引用回答、检索质量与评测集、Agent 工具调用的幂等/重试、提示注入与数据边界、延迟/成本权衡、线上可观测性与回归评测     |
| 系统设计  | 从需求澄清开始完成 API/数据模型、容量与瓶颈、缓存/异步任务、失败/重试/一致性、安全与权限、监控/告警/回滚的设计说明                   |
| 项目深度  | 用一个真实项目说明个人责任、问题与成功指标、备选方案和取舍、关键技术难题、量化结果、生产故障或性能问题、跨团队协作和复盘改进         |

项目深度维度有额外真实性约束：无法说明个人贡献、技术取舍和至少一项可验证结果时，该维度最高只能得到 2/5 分，并由 Coach Agent 要求补充事实，而不是代为编造。

### 4.5 授权辅助模式

- 显示明显的录音状态、授权声明与停止按钮。
- 只提供实时字幕、时间提示、面试要点和会后摘要。
- 默认关闭系统音频采集；开启前由用户选择音源并确认已取得授权。

## 5. Agent 设计

不要使用一个无边界的通用 Agent。将职责拆分为可测试、可观测的模块：

| Agent             | 输入                         | 输出                         | 约束                         |
| ----------------- | ---------------------------- | ---------------------------- | ---------------------------- |
| Profile Agent     | 简历、用户补充信息           | 结构化经历、技能、可引用证据 | 不补造事实                   |
| Job Agent         | JD、岗位设置                 | 能力模型、考点和评分标准     | 标明不确定解析项             |
| Interviewer Agent | 会话状态、能力模型、历史表现 | 下一题、追问、澄清问题       | 题目与目标能力绑定           |
| Coach Agent       | 回答、简历/JD 证据           | 评分、缺口、改进建议         | 建议必须可追溯               |
| Report Agent      | 完整会话、评分、趋势         | 会后报告、训练计划           | 区分事实、推断和建议         |
| Safety Agent      | 用户请求、模式、权限状态     | 允许/拒绝/需确认             | 拦截作弊、隐私与虚构经历请求 |

### 5.1 会话状态与检索

Agent 编排器维护小而明确的会话状态：

```text
profileId + jobId + interviewPlan + currentCompetency
+ recentTurns + selectedEvidence + consentState + mode
```

其中 `selectedEvidence` 来自简历、JD、用户确认的故事库和历史弱项。每轮只检索与当前能力维度最相关的资料，避免把整份简历与所有历史对话塞入上下文，降低成本和幻觉风险。

### 5.2 输出契约

模型输出必须先通过 Zod/JSON Schema 校验，再显示给用户。核心契约如下：

```ts
type CoachingCue = {
  competency: string;
  score: 1 | 2 | 3 | 4 | 5;
  strengths: string[];
  gaps: string[];
  nextAction: string;
  evidence: Array<{
    source: 'resume' | 'job_description' | 'answer' | 'history';
    quote: string;
  }>;
};
```

## 6. 技术方案

### 6.1 总体架构

```text
┌──────────────── Electron Desktop ────────────────┐
│ Vue 3 UI / Pinia / 本地加密缓存 / 系统权限管理   │
│ Main Process ─ Preload 白名单 ─ Renderer          │
└───────────────────────┬──────────────────────────┘
                        │ HTTPS / WebSocket
┌───────────────────────▼──────────────────────────┐
│ NestJS API                                        │
│ Auth | Profile | Job | Interview | Report         │
│ WebSocket Gateway | Agent Orchestrator            │
└───────────────┬───────────────────────┬───────────┘
                │                       │
      ┌─────────▼─────────┐   ┌─────────▼─────────┐
      │ PostgreSQL+pgvector│   │ Redis + BullMQ     │
      │ S3 兼容对象存储    │   │ 文档/报告异步任务  │
      └───────────────────┘   └───────────────────┘
                │
      ┌─────────▼─────────────────────────────────┐
      │ 云端模型适配层：LLM / Embedding / 流式 ASR │
      │ Provider Adapter / 降级与用量控制          │
      └───────────────────────────────────────────┘
```

### 6.2 云端优先模型策略

“云端优先”是本项目已经确定的部署策略：Electron 不下载或运行大模型，所有文档解析、向量化、语音识别、对话推理和报告生成都由 NestJS 调度云端模型服务完成。

```text
Electron 采集简历、文本或麦克风音频
  -> TLS 加密传输至 NestJS
  -> 云端文档解析 / 流式 ASR / Embedding / LLM
  -> PostgreSQL、对象存储与向量检索
  -> Electron 展示字幕、追问、反馈与报告
```

- Electron 只负责界面、系统权限、音频采集和必要的加密缓存；不保存模型厂商永久 API Key。
- NestJS 负责签发会话、调用 Provider Adapter、控制用量、脱敏日志、失败降级与重试。
- 云端优先能以较低的客户端复杂度快速获得稳定模型效果，适合 MVP；代价是网络依赖、持续推理成本和更严格的数据治理要求。
- 本地 Whisper 或本地向量检索不进入 MVP，仅在后续面向高隐私需求用户时作为可选模式评估。

### 6.3 DeepSeek 生产配置、地域与预算

以下配置基于 [DeepSeek API Quick Start](https://api-docs.deepseek.com/) 和 [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing) 于 2026-08-24 的公开文档。模型以稳定别名调用，而不是锁死某个发布日期版本；官方说明别名会指向最新版本。

```text
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL_PRIMARY=deepseek-v4-pro
DEEPSEEK_MODEL_FALLBACK=deepseek-v4-flash
```

| 场景                             | 模型                | 调用策略                                                                  |
| -------------------------------- | ------------------- | ------------------------------------------------------------------------- |
| 深度解析、系统设计评分、最终报告 | `deepseek-v4-pro`   | 主服务；开启推理模式，使用受控输出 token 上限                             |
| 题目分类、报告摘要、非计分追问   | `deepseek-v4-flash` | 主动节流任务与主服务不可用时的降级服务                                    |
| 简历/JD 深度解析、动态追问       | `deepseek-v4-pro`   | 若触发熔断或预算降级，则返回 `deepseek-v4-flash` 的降级结果并在事件中标记 |

官方公开价格以美元/百万 token 计费，且低谷价格为高峰的一半。预算计算统一使用高峰价，并将每次调用的价格版本写入用量账本：

| 模型                | 输入缓存命中 | 输入缓存未命中 |     输出 |
| ------------------- | -----------: | -------------: | -------: |
| `deepseek-v4-pro`   |    USD 0.044 |       USD 1.32 | USD 3.96 |
| `deepseek-v4-flash` |    USD 0.014 |       USD 0.44 | USD 1.32 |

预算仅覆盖 DeepSeek 文本模型用量，不含后续阶段的 ASR、对象存储和带宽。按 **每位活跃用户每自然月人民币 50 元** 执行，采用保守汇率 `1 USD = 7.5 CNY` 和高峰价：

1. 标准 60 分钟练习单场限制为 `deepseek-v4-pro` 输入 150K token、输出 20K token，峰值估算约 2.1 元；达到单场限额后只允许必要追问。
2. 月度 35 元预警，42.5 元起将非关键任务路由到 `deepseek-v4-flash`，50 元硬性停止新的生成任务。
3. 按 `userId + month` 进行原子额度扣减；每次记录模型、输入/输出 token、缓存命中、任务类型、美元单价、汇率和人民币估算成本。
4. 价格页面变更时，更新服务端价格表版本；超过 5% 的费用差异阻断自动发布并触发人工复核。

地域策略明确如下：应用服务、PostgreSQL、Redis 和对象存储部署在 **阿里云华东 2（上海，`cn-shanghai`）**。DeepSeek 公共文档只提供单一 `https://api.deepseek.com` 入口，未声明可选择的推理地域或对外 SLA；因此 MVP 不对外承诺模型请求的数据驻留地或供应商 SLA。发送前必须剔除姓名、电话、邮箱、地址和证件号等直接身份信息；企业版上线前必须取得供应商书面数据处理协议与地域承诺。

应用自身的服务目标（不是 DeepSeek SLA）为：API 月可用性 99.5%，`deepseek-v4-pro` 首 token 超过 8 秒或总响应超过 45 秒触发一次重试，重试失败后降级至 `deepseek-v4-flash`；`deepseek-v4-flash` 对应阈值为 4 秒和 30 秒。官方账户级并发上限为 Pro 500、Flash 2500，MVP 将应用侧并发限制为 Pro 30、Flash 100，以保护成本和下游稳定性。

### 6.4 服务端凭据管理

1. NestJS 运行在阿里云 ACK，使用 RAM 工作负载身份读取阿里云 KMS 保护的 Secrets Manager；生产环境不使用静态 `.env` API Key。
2. 为开发、预发、生产环境配置独立 DeepSeek API Key；密钥不进入 Git、数据库、日志、Electron 安装包或 renderer 进程。
3. 密钥明文只在 API 进程内存中短暂存在；每 90 天轮换一次，使用双密钥 24 小时灰度，发现泄露立即吊销并轮换。
4. 调用 DeepSeek 时传入不含个人信息的 `user_id`：`ds_` 加用户 UUID 的 HMAC-SHA-256 截断值，以利用官方的用户级隔离能力而不暴露真实身份。
5. Provider Adapter 统一注入 `baseURL`、密钥、模型别名、超时、并发器和熔断器；业务模块只能传入任务类型和已脱敏的上下文。

### 6.5 前端与桌面端

- `Vue 3 + TypeScript + Vite + Pinia + Vue Router`：渲染进程和业务 UI。
- `Electron Forge` 或 `electron-vite`：打包、自动更新、主进程构建。
- Electron 必须启用 `contextIsolation: true`，禁用 `nodeIntegration`，仅通过 preload 暴露类型化 IPC。
- 本地只缓存必要数据；敏感令牌使用操作系统安全存储，练习缓存使用 SQLCipher/平台级加密。
- 录音/桌面音频必须使用系统权限 API，并保留可见的状态提示。

### 6.6 NestJS 服务端

- REST API：认证、档案、JD、会话、报告、文件元数据。
- WebSocket Gateway：流式音频、部分转写、Agent 状态和字幕事件。
- BullMQ Worker：文档解析、向量化、长报告、音频后处理、删除任务。
- Prisma 或 TypeORM：数据库访问；DTO 与 `packages/contracts` 中的 Zod schema 对齐。
- 对外模型调用封装为 Provider Adapter，不允许业务模块直接绑定单一模型厂商；首版必须配置主服务与故障降级服务。

### 6.7 推荐仓库结构

```text
apps/
  desktop/                 # Electron main、preload、Vue renderer
  api/                     # NestJS HTTP 与 WebSocket 服务
  worker/                  # BullMQ 异步消费者

  agent-core/              # 检索、上下文组装、Agent 策略、评估规则

  config/                  # ESLint、TS、环境配置
infra/
  docker/                  # PostgreSQL、Redis、MinIO、本地开发
docs/
  interview-assistant-agent-solution.md
```

## 8. 隐私、安全与可靠性

- 传输使用 TLS；对象存储和数据库敏感字段加密；密钥使用独立密钥管理服务。
- 默认设置数据保留期限；支持下载、删除、撤回授权和账号注销。
- 录音前强制确认；企业版增加候选人知情、组织权限、审计日志和数据隔离。
- 模型提示词中不包含永久密钥；原始音频、简历和 JD 不进入应用日志。
- 云端模型服务需完成供应商准入、数据处理协议、数据地域与保留政策审查；禁止将用户数据用于未获授权的模型训练。MVP 不承诺 DeepSeek 推理地域，企业版必须补齐书面承诺后才能处理原始企业数据。
- 对 AI 输出做 schema 校验、敏感信息过滤、速率限制、失败降级和重试。
- 对“是否录用”不生成自动化结论；所有分数仅用于训练反馈。

## 10. 首版指标

- 每条关键反馈均带至少一个简历、JD 或回答原文证据。
- 模拟面试结束后 30 秒内生成报告。
- 转写部分结果 P95 小于 1.5 秒，实时辅导事件 P95 小于 2.5 秒。
- 用户可在设置中查看、导出和删除个人训练数据。
- 模型厂商 API Key 仅保存在服务端，桌面安装包与渲染进程中不可获得。
- 总分严格按 Vue/React 10%、AI 应用 20%、系统设计 30%、项目深度 40% 聚合，并提供维度级证据。
- 服务端在预算阈值下执行 `deepseek-v4-pro` 到 `deepseek-v4-flash` 的可观测降级，单活跃用户每自然月模型成本不超过 50 元。
- 题库按 12/24/36/48 的比例覆盖四个评分维度，并在每场标准模拟中覆盖规定的核心题。
- 不存在规避检测、隐藏录制、未经同意实时作答等功能路径。

## 11. 已确认决策与下一步

已确认：

- 首批用户为 3-5 年经验的前端与 AI 技术求职者。
- 模型采用云端优先部署。
- 评分权重为：Vue/React 10%、AI 应用 20%、系统设计 30%、项目深度 40%。
- 云端主服务为 `deepseek-v4-pro`，降级服务为 `deepseek-v4-flash`，入口为 `https://api.deepseek.com`。
- 模型成本按每位活跃用户每自然月 50 元执行，采用服务端原子额度、35/42.5/50 元三级阈值。
- 题库共 120 题，按 Vue/React 12、AI 应用 24、系统设计 36、项目深度 48 分配，并定义了各自的 L1/L2/L3 比例和核心题。
- 应用数据部署在阿里云华东 2（上海）；不对 DeepSeek 公共 API 作未经合同支持的地域或 SLA 承诺。
- 凭据由 ACK 工作负载身份和阿里云 KMS/Secrets Manager 管理，Electron 不接触 API Key。
